# TopoMem v4.1 选择、晋级与封存

每轮开始时封存训练档案的可见视图。活动父代与提议子代使用同一个自适应视图，固定对照使用独立的档案和初始生成器。每条候选分支的后续槽可以读取本分支前一槽的单次粗测、程序和反馈。其他分支的当轮结果在这一阶段不可见。槽位、模型调用上限和裁判条件由控制器配置固定。来源见 `topology_rsi_v4.py` 的 `_previous_context`、`_new_trials` 和 `_round`。

## 重复训练与三条选择线

训练矩阵纳入本轮已组装的程序、上轮三个选择结果及历史管理器参考。控制器先封存矩阵、效应代表和执行顺序，再在相同训练用例上重复至少三个区块。一个训练身份在同一矩阵中使用一个代表程序，但不同提案的原始程序摘要、实际生成源码和编辑父代均保留。粗测用于下一槽提示，最终选择读取同一矩阵内的完整重复观测。正确性失败排除对应效应，测量未结算会阻止本轮选择。

训练优势要求相对比较对象的每块收益为正，且配对中位收益严格超过配置的训练差异门槛。选择器保留未被稳健击败的效应集合。当前线的合格保留项仍在集合中时沿用它，其余情况按效应摘要与提案 ID 确定代表。因此 `manager_best` 表示本轮训练协议选出的管理器，范围是当轮候选和保留项。

| 选择线 | 训练候选及来源 |
| --- | --- |
| `manager_best` | 自适应池的管理器。可以由晋级失败的源码提出，报告保留实际来源。 |
| `admitted_output` | 自适应池中由初始源码或已晋级源码直接提出的程序。先筛选实际提出程序的源码，再进行训练选择。 |
| `fixed` | 固定池的初始生成器产物。固定臂元调用的提议源码不激活。 |

父、子源码的验证使用各自本轮新提案选出的输出，历史管理器单独作为 incumbent 参考。两函数 AST 均需变化，并且在匹配起点上观察到任务入口和元入口的结构决策变化。调整证据 ID 顺序不计入变化，父代顺序仍有意义。子代训练身份须区别于父代与 incumbent。晋级还要求子代通过相对两者的固定配对验证门槛。训练差异门槛与配对验证门槛各自取配置值。

## 源码资格、祖先与实际复用

直接来源资格检查实际提出程序的生成器摘要。已晋级源码可以编辑被拒绝源码留下的程序。完整编辑祖先资格沿全部父代边检查，接受受信 bootstrap 和无父代的合格提案作为起点，结果只作诊断。由被拒绝源码提出的程序可以进入 `manager_best`，也可以成为未来提案的编辑父代。

每轮元响应提交候选源码和评估前方案。台账记录选中的训练证据、方案、候选摘要、源码差异、父子实际任务调用及验证裁决。晋级后的下一轮从归档读取新源码，并核对完成的任务调用、实际生成程序与元调用是否都绑定新摘要。控制器还在相同训练视图上用旧源码重放元入口，检查实际元决策是否改变。`recursive_behavior_observed` 需要上述调用证据和元决策差异。末轮晋级若尚无后续调用，只能记录源码晋级。训练矩阵、受信选择器、目标资格与预算属于人工协议版本，归因以本轮模型实际产生并激活的源码为准。

封存取最后已结算轮的三项训练选择，绑定清单、轮次和最后训练矩阵摘要。`test` 才打开本次搜索隔离的测试分区，并分别将 `manager_best` 和 `admitted_output` 与原生、固定及适用的手写策略配对。留出结果不回流选优。CUDA v4 的训练身份是原始程序的规范 JSON SHA-256，采用保守的原始程序身份。两个不同摘要可能执行相同的物理布局，物理等价需要另外的执行证据。来源见 `cuda_v4.py` 的 `exact_program_identity` 与 `contract_domain`。

## 未知状态与已发现的实现边界

- 已记为 `pending` 的外部调用在恢复时转成 `interrupted_unknown`，原身份不会自动重发。模型未知调用留档，其他候选仍可继续。粗测未知或失败会停止本轮训练。重复矩阵出现未知效果、缺失收据或收据不合法时保留未结算状态，不能用于选择。默认封存要求完成配置轮数，命令行的部分封存需显式启用。
- **v4.1 修复了元提示中的旧选优说明。** 原始 v4 试跑继承的提示允许父子保留共同历史最优，与实际 fresh-output 比较冲突；该试跑已停止并独立归档。v4.1 的实际模型请求使用 `META_SYSTEM_V41`，移除旧句，并发送清单绑定的 `trusted_selection_contract`。此项由人工修复，不计为模型递归改进。
- **自主改动范围限于显存 IR 与生成器双入口。** 完整控制器和执行后端由人工维护，跨运行语义知识库的自主迭代尚未实现。作业记录持久化属于人工受信基础设施修复，受影响的历史作业保留未知状态。 [自主迭代边界及持久化修复](AUTONOMY_BOUNDARY_ZH.md)
- **结构见证对逐槽反馈存在漏检。** `_new_trials` 的第二槽可见本分支粗测，继承的 `_behavior` 则用轮首视图逐槽重放。只在收到当轮粗测后改变操作的源码，可能确实改变实际执行却被结构门槛拒绝。相反，轮首反事实里的槽位差异也可能在收到粗测后消失。当前实际后轮复用台账只对元入口做同输入旧源码反事实，任务侧证明调用归属与实际产出。
- **重复回执防线以整组为单位。** 矩阵拒绝完全重复的有序 receipt 列表，无法单独识别不同列表中的同一个计时 receipt。当前 CUDA 单次训练评价只报告一个作业 ID，这条检查能捕获其作业 ID 重复。若以后接入同时报告资格和计时回执的适配器，需要单独绑定计时作业身份。

协议源码为 `rsi_memory/topology_rsi_v4.py`（当前版本 4.1）、`selection_protocol.py` 与 `cuda_v4.py`。工程复评复用已公开的 Agent、Chatbot、长文和 Rollout 语料。最初的 H256 双卡配置在宿主重启后中断，四案各自在预先分配的单张计算卡上运行。每次运行的张量规模、计算映射和实际硬件占用以各自冻结清单和原始回执为准。 [H256 中断证据](../results/cuda-v41-reboot-interruption/README_ZH.md)

训练及验证门槛按各次运行的配置预先固定。H256 工程复评的两道门槛均为 2 ms，表示预先规定的实质差异，未从该几何的训练 A/A 分布估计。
