# 显存管理与框架的自主迭代边界

人的主要工作是指定任务边界、执行和复核测试、提交可重现的故障与问题反馈。显存方案、搜索策略和下一轮要验证的改进由框架提出。候选规则的取舍、调参和性能补丁默认交给框架。用户明确要求的人工工程改动单独登记，并保留实际提出者和实现者。

## 当前已经实现

- **生成显存管理程序。** DeepSeek 在目标提供的动作和特征内生成 `MemoryProgram` IR。受信编译器和执行后端验证程序，在固定注意力、硬件拓扑、应用场景及外部调度下执行。 [架构与后端范围](ARCHITECTURE_ZH.md)
- **生成器可自改。** `build_prompt` 选择构造、变异或交叉，以及父代、训练证据和规则焦点。`build_meta_prompt` 选择修订策略和证据。一次元模型响应提交两个入口的候选源码和改进方案。控制器在评估前封存候选摘要与方案，用固定门槛和配对结果裁定晋级。后续实际任务调用、元调用与同输入旧源码重放用来检查晋级源码的影响。 [v4.1 选择、晋级与封存](V4_SELECTION_PROTOCOL_ZH.md)
- **训练档案提供当前搜索上下文。** 档案保存程序、生成器来源、测量、失败与反馈。现有控制器对这些记录执行既定选择。跨运行的语义知识库、知识检索策略和知识验证状态尚未进入自主晋级链。完整框架控制器、受信编译器与显存运行时目前也由人工维护。 [训练档案与三条选择线](V4_SELECTION_PROTOCOL_ZH.md)

v12 动态特征按需计算与 v13 零跳 producer 保留均由人安排、Sol 编写。v12 在既有 writeback IR 上相对 v11 的四场景合计 0/8 胜，配对中位慢 9.900174 ms，未合入默认 GPU 运行时。v13 在同一 LRU 等价 IR 上相对 v11 8/8 胜，配对中位快 11.661276 ms，相对项目原生直写/LRU 参考 0/8 胜，配对中位慢 11.449308 ms。v13 合入的是已资格的执行优化。两组均来自单 GPU 工程对照，归因保持为人工工程。 [v12 实测](../results/engineering-dynamic-v12/README_ZH.md) · [v13 实测](../results/engineering-producer-v13/README_ZH.md)

H256 工程复评遇到宿主重启，一项 GPU 作业的请求、输入、启动记录和进程日志均为 0 字节。之后由人工修复受信执行工作进程的持久化路径。工作进程写入的 JSON 在原子替换前先刷新并同步文件，POSIX 上另同步相关目录，启动前完成作业预留记录的同步。作业目录已存在但记录损坏或缺失时保留 `started_unknown`，原标识禁止重提。历史作业的 `transport_unknown` 状态继续保留。修复限于工作进程记录，未覆盖子进程原始日志或结果文件的持久性。12 项协议测试在 Windows 和 Linux 均通过，包含真实临时文件、POSIX 目录同步和故障注入；没有进行实际断电恢复验证。 [Linux 原始测试记录](../results/operations/worker-durability/test-report.json) [中断记录](../results/cuda-v41-reboot-interruption/README_ZH.md) · [修复源码](../rsi_memory/execution_worker.py) · [测试](../tests/test_execution_protocol.py)

留出阶段的终局状态也由人工修复。配对作业失败或执行状态未知时报告 `test_incomplete`，完成但存在不可行臂时报告 `test_infeasible`。两者保留原始效果记录，命令行返回非零。所有臂均完成且可行后才封存比较并报告 `test_settled`。历史归档仍以各次冻结源码和原始回执复核。 [控制器](../rsi_memory/topology_rsi_v4.py) · [测试](../tests/test_topology_rsi_v4.py)

## 目标中的可变项与受信边界

以下是后续实现的职责划分。每次运行预先声明实际允许的改动范围。

| 框架可提议的版本变更 | 固定控制面 |
| --- | --- |
| 显存程序和后端候选，例如 KV 放置、移动、保留和回收的实现。后端候选通过隔离执行和受信校验后才有资格晋级。 | 注意力语义和选集契约、GPU 及拓扑、模型与固定输入，以及调度、准入、批次和计算位置。 |
| 生成及搜索策略，例如固定预算内的候选槽分配、父代与操作选择、去重、局部实验和失败后的探索方式。 | 调用、评估、时间和容量预算，正确性裁判、验收门槛、测量口径、对照程序及留出访问权限。 |
| 知识条目及其检索策略，例如提取有据可查的观察、优先检索适用的反例或淘汰失效摘要。 | 原始回执、证据身份与分区、凭据、执行权限、记录和裁决的完整性。候选代码只通过受控接口访问这些资源。 |

## 目标循环与验收证据

1. **提出并封存。** 当前框架读取获准的训练证据和知识快照，提出候选程序、代码差异或知识变更，并写明预计效果、适用范围和证伪条件。执行前记录提案来源、父子源码与知识快照摘要，以及变更实际触及的决策或行为。
2. **隔离测试。** 候选先通过针对其变更的正确性检查。显存后端候选使用受信裁判核验输出和选中 KV、生命周期、容量及外部输入；框架与知识候选还须验证权限、预算和证据隔离。保留失败和未知状态，未知外部效果不得自动重发。
3. **配对验证。** 在预注册条件下比较候选、当前父代、已有强方案和适用的固定对照，配平调用与评估预算。后端或框架更新要有单独对照，以便区分执行器改进、搜索变化和知识变化。保留逐块结果与拒绝理由。最终选择在打开留出分区前封存，留出结果不进入该轮选择或知识输入。
4. **由受信控制面裁定晋级。** 只有独立正确性和配对门槛均满足时才激活新版本。提案的预期属于假设，候选产出的测试报告也须接受独立核验。晋级台账记录实际激活的源码与知识快照，拒绝版本保留原始证据。
5. **核对下一轮实际复用。** 真实任务与元请求记录已激活的源码摘要、实际检索的条目和知识快照摘要。用同输入旧版本重放核实实际策略或证据选择变化，并检查新代码确实执行。仅有源码差异、文字改写或末轮晋级，证据至多支持改动或晋级。后续版本还能依据本轮证据提出并实测新的改进，才形成多轮复用链。

## 知识条目的最小契约

| 类型 | 内容与核验 |
| --- | --- |
| 观测 | 记录裁判实际测得的量、单位、对照和结果，绑定回执与受信核验状态。 |
| 假设 | 记录拟解释的现象、预期效果、证伪条件与依据。无直接验证时标为待测。 |
| 反例 | 保存同一假设在已测条件下失败的输入、对照、原始结果和回执，限定反例适用范围。 |

每条记录绑定注意力实现、后端及源码版本、拓扑、场景、输入分区和相关程序摘要。提案可引用已有证据；没有实测回执时保留待测状态。验证字段由受信控制面根据独立回执写入，模型只能提出条目与更正。条目升级、撤回和反例要随知识快照留痕。

发布自主迭代结论时分别报告内存程序对原生及强手写对照的表现、生成器对同预算固定臂的表现，以及框架代码和知识快照在哪些后续调用中确实改变了行为。当前证据覆盖程序生成与两个生成入口的受限自改，框架代码、后端和语义知识库的共同自主迭代仍待实现和实测。
