# SGLang v3 正式结果独立审计

正式递归臂的封存程序对原生、固定种子和手写对照的三项登记比较均未通过。固定种子直接生成的 6144 槽全驻留程序在正式留出的 12 个区块全部快于本实验原生 4096 槽对照。两轮源码均未晋级，没有晋级源码的后续调用。

## 封存来源与源码改进

- 主递归臂选中种子源码的 R0 parent/01，程序 SHA-256 为 be70b6cc987e6a8ad0ee9664a41609731ff360dacf35e532080dcee74977ecd1。两个测试用例均使用 4096 槽，两个 rank 的第 0 层冷备份在各自本地 HBM，其余五层使用 pinned host。本实验原生 4096 槽对照的六层均使用 pinned host。
- 固定臂选中种子源码的 R0 fixed-a/00，程序 SHA-256 为 dc3ca18c68bfb509c90bc634cd260e84c05f519ff181c5b0949a7ed955efa3f4。其全驻留布局与 38 作业训练 sweep 选中的手写对照相同，冷主机 payload 为 0 B。
- 档案最佳来自 R0 被拒绝子源码的 child/00，程序 SHA-256 为 faebc28591a6af32ce3461738fa05608deb4b1be65cde09f944021ba2c77d083。它同样为 6144 槽全驻留，档案验证分值为 1070.8233845 ms。正式主封存按预先规则排除其未晋级谱系。
- R0 子代相对选中的父代 5/6 区块正收益、配对中位 +14.3297835 ms，v4 为 −4.614906 ms。子源码在同起点的两个任务槽只逆转同一批证据 ID 的次序，元入口从 revise 改为 rethink 来自影子检查。R1 的实际元调用仍用种子源码并选择 revise。
- R1 父代和子代都保留同一 R0 档案 incumbent。固定臂也因同物理配置保留自己的既有程序。R1 的拒绝原因为 child_retained_incumbent。两轮共 20 次已结算的 DeepSeek 调用，递归与固定各 10 次，提供者报告总用量分别为 136466 和 146005 tokens。[两轮验证审计](v3-two-round-validation-audit.json)

6144 槽全驻留是先经独立工程探针验证、再进入正式搜索空间的人工受信原语，训练 sweep 也已将其选作最强手写对照。种子父代和固定种子都能生成与 R0 子代同物理的全驻留程序。R0 父代在单次训练计时中把快 0.007183 ms 的 4096 槽候选选为输出，实际排序对计时波动敏感。自动生成确实产出了可用配置，证据未显示递归改写带来额外改进。不同 GPU 执行的配对区块共用已封存程序，独立生成器重复仍待检验。

历史 CUDA 实验与 SGLang 的证据对象不同。CUDA v7 的 R2 有一次源码晋级和后续实际复用，封存显存程序对项目原生直写/LRU 的留出为 0/12，晋级源的四场景迁移对该参考为 0/48。SGLang 固定种子产出在本双卡回放上达到对本实验原生 4096 槽对照的实测改善，正式递归臂及源码改写均未达到各自的预登记目标。

## 适用范围

实机使用两张 RTX 5090 的 backbone TP2 与 attention DP2，两个 GPU 都执行 attention。该机的目标卡之间无可用的 GPU 直连 P2P。GPU 经 pinned host 中转至对端 GPU 的显式路线已在独立探针中通过资格。本次正式封存及补充比较各臂的对端 GPU KV 用量均为 0，所测全驻留来自各 rank 的本地热 KV。回放使用随机初始化后以玩具文本微调的 tiny GLM，输出为 EOS，范围为固定架构回放的正确性与计时。下一独立实验可检验重复配对训练计时能否稳定候选排序，以及跨独立生成器重复能否重现源码改进。


## 离线复核
