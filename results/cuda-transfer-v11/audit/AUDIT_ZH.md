## 行为与执行路径

两源在每个场景封存了不同的 IR。四场景 96 个留出配对用例中，去除规则编号后，有序动作及生命周期记录均相同，链路字节、缺页、受管预留和峰值也一致。Agent、长文和 Rollout 的诊断工作计数相同。Chatbot 的放置路径不同。每次完整诊断中，两个用例的初始源分别运行 356、296 次通用放置选择，扫描 1,068、888 个候选。晋级源对应执行 356、296 次静态路线选择。记录支持同一显存行为下的执行路径差异，未单独计时解释器成本，也未观察到新放置或传输机制。

四场景都租用两张实际 GPU。四臂在非计算 GPU 的受管 KV 峰值和相关有向链路字节均为 0。实验在多卡拓扑约束下执行，留出结果没有第二卡 KV 利用证据。[逐用例动作与工作计数](audit.json)

## 选择、隔离与回执

- 对照 v7 台账逐字节核对初始源 `42699e4d5148ee3dc3f41f7ffeab8a3020e8fb75a5a433940d7ae88e4c08ca38` 和唯一 R2 晋级源 `7d9d37e11e08ac084b3b2b4eb3579178652fc5258dc53c2f502b0f995621c201`。固定 `round=2`，每源每场景两槽。重新执行受限 `build_prompt`，逐一重建 16 条请求、上下文、选中证据和响应程序。两源各 8 次实际模型请求，报告总用量分别为 232,414 和 168,743 tokens，合计 401,157。本次只执行生成入口。
- 四个场景各两个训练和两个留出用例。重算固定用例与编译后的调度身份，训练和留出内容摘要没有交集。实际模型信封从训练用例和三类训练锚点重建。信封未包含留出用例名、内容摘要或用例摘要。16 个槽均生成合法 IR，14 个训练可行。Agent 初始源槽 0 和长文晋级源槽 0 因 `InfeasiblePlan` 被淘汰。八个入围程序都是各源各场景的最低可行训练分。SQLite 结算顺序显示选择封存在首个留出作业之前。
- 重算 220 份 GPU 作业的请求、规范化结果和原始结果摘要，其中留出 192 份、训练锚点 12 份、训练候选 16 份。逐份核对冻结源码、CUDA 设备绑定、有效退出、清理、用例与程序。384 个留出用例报告各含一次正确性诊断和三次正式计时，共 1,152 个计时值。逐区块复算用例中位数、配对增益和校正区间。诊断报告记录的选中 KV 与输出摘要在各臂一致。本审计未重跑 GPU。

Agent 复用了 v7 实际进入留出评估的两个用例，属于同域换执行器复测。其余三个场景沿用既有封存用例。该实验比较已有两版生成器在 v11 执行器上的产出，未新增递归轮次。结果适用于固定的合成稀疏注意力任务，真实模型服务须另行验证。[阶段台账](../journal.sqlite) · [生成工件](../generated.json) · [训练选优](../selected.json)
