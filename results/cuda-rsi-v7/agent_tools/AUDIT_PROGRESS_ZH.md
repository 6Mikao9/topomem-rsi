DeepSeek 返回的源码与归档 `7d9d37e11e08ac084b3b2b4eb3579178652fc5258dc53c2f502b0f995621c201` 字节一致并通过受限源码校验。控制记录显示两个入口 AST 均变化。同起点任务槽 0 从 `construct` 改为 `crossover`，槽 1 仍为 `mutate`，规则编号从 0 改为 5。任务证据重排。元入口从 `revise` 改为 `repair`，证据重排。两臂各发起五次 API 请求，provider 报告用量分别为递归臂 142,011 和固定臂 128,955 tokens。

### 历史最佳对照

前两轮的最佳递归臂入围程序是 R0 `parent/01`，SHA-256 `d1e9e20295e0859d73ecbb16f1dd6dc275b1aac486391038da9751fb0d8013b8`，验证中位数 142.544517 ms。R2 入围子代 `child/00` 的 SHA-256 为 `b1b449ad1d4064b82104c82d84edb3c538082ecdbe990d4befe0d5dd2f224cee`。其前六条规则与历史最佳逐条相同，第七条是 R1 `parent/01` 捐出的首条 `allocate/place`。同组第一条规则的 `when` 恒为正，因此先命中，第七条不会被选中。规则 5 的回收改写来自另一个候选 `child/01`。

按相同区块和场景对比历史最佳与 R2 子代的 24 次诊断，完整有序动作、链路字节、缺页、各节点管理峰值与选中输出摘要均一致。R2 中位数比历史最佳的点估计慢 0.1719685 ms，这两个估计来自不同轮次的测量。R2 的效应是利用档案避开当轮新生成父代的退步，恢复已观察的最佳行为。

## R3 真实复用与后续裁决

R3 的实际 `api/r0003/adaptive-meta`、`api/r0003/parent/00` 和 `api/r0003/parent/01` 全部完成并绑定 R2 晋级源码 SHA。两次任务请求生成了合法程序 `ecb165685aae02b5…` 和 `59a0407359695fe9…`，两份独立 GPU 训练回执均可行，分值分别为 114.053286 和 115.029822。结算记录的 `previous_admission_reuse` 也指向这三个实际调用和两个程序 ID。

R3 元请求使用 R2 训练反馈，记录了 R2 局部低复制候选、慢候选和生产者容量不可行结果。实际返回的新方案拟将任务槽 0 改为对规则 5 的变异、槽 1 改为交叉，并将当轮元模式从 `rethink` 改为 `repair`。返回源码与归档 `c541febcf6bba354693cddda70904d7a99ab8369d43e6a2f2ccad163a8a325ce` 字节匹配，受限源码校验通过，方案在候选评估前落盘。R3 结算记录显示两个入口 AST 和同起点结构决策均变化。

R3 新子代相对活动父代胜出 11/12，配对差中位数 +1.966604 ms，另一个区块退化 0.241434 ms。按既定全区块门禁拒绝，活动源码仍为 R2 版本。子代相对 CUDA 参考胜出 0/12，配对差中位数 −21.187641 ms。R3 的 72 份配对回执也通过源码、结果摘要和逐区块六臂正确性核对。

## R4 和 R5 实际影响

R4 的两次任务调用和元调用继续执行 R2 活动源码 `7d9d37e11e08…`。元调用返回 `2b844f41a600…`，源码与存档一致。方案把偶数槽改为变异、奇数槽改为交叉，并将当轮元模式改为 `revise`。两个入口 AST 和同起点结构决策均变化。入围子代的原始程序 SHA 与 R0 历史最佳 `d1e9e20295e…` 完全相同。验证中位数为子代 142.815108、父代 143.2443885、CUDA 参考 120.5499265 ms。子代只胜过父代 8/12，配对中位差 +0.638987 ms，最差区块退化 2.748866 ms。相对 CUDA 参考为 0/12，配对中位差 −22.0073955 ms。R4 拒绝晋级。其 72 份回执均通过摘要及逐区块正确性核对，子代第二张 GPU 的管理 KV 峰值为 0 B。

R5 的两次父代任务和元调用同样绑定 `7d9d37e11e08…`。元请求实际返回新计划和源码 `d59387f979b599f3e041d94d3c6946a50a8ef2d486079d56a8d1903a80a85363`。计划在两个子代任务调用前写入台账，提出偶数槽改为变异规则 4、奇数槽改为构造，并改变元入口模式和证据次序。按实际起始档案复放，两个 AST 和结构决策均变化。两次父代和两次子代训练裁判各有一个可行结果，分别为 114.8362 与 115.003929 ms。固定臂收到元方案，源码受限校验拒绝，固定生成器继续使用种子。

R5 验证中位数为子代 144.376543、父代 144.2956525、CUDA 参考 121.0291635 ms。子代相对父代为 7/12，配对中位差 +0.255027 ms，最差退化 7.232673 ms。相对 CUDA 参考为 0/12，配对中位差 −23.2882495 ms。相对手写为 12/12，配对中位差 +16.654031 ms。R5 未达到逐区块全胜和 0.5 ms 门槛，保持 R2 源码。72 份唯一回执的源码清单、规范化结果摘要和区块分值一致，12 个区块内六臂的固定场景及选中 KV 与输出摘要一致。

## 独立 SGLang 基线资格

**证据范围为 tiny-model 固定回放的机制测试。** SGLang 探针固定 `inference-optimization/GLM-5.3-0.6B-A0.4B` revision `20aae340d157bd2215b9d81165be87e94686dfdf`。该模型经随机初始化和少量玩具文本微调，用于架构测试。当前回放的输出序列均为 EOS。任何配对时延结果限于该模型、冻结回放和运行合同，训练后生产模型的 KV 局部性与 Agent、LongBench 等业务质量仍需独立证据。 [固定版本模型卡](https://huggingface.co/inference-optimization/GLM-5.3-0.6B-A0.4B/blob/20aae340d157bd2215b9d81165be87e94686dfdf/README.md)

独立 stock SGLang smoke 采用 TP2 主干和 attention DP2，每个 attention rank 实际派发一个请求，两 rank 都记录八个本地 query heads，输出 ID 一致。该已验证 smoke 的回执记录 NCCL override 文件 SHA-256 `651cf05af28976ca8d996f4e2750e69db1fa427667ee3405b9e576e9d2960eaf`。已核对归档及该结果文件摘要。[SGLang 资格证据清单](../../sglang-qualification/evidence_manifest.json)

SGLang 6,144 hot slots 的 stock 强对照目前有六份绑定工件，状态均为 `built_unverified`。它们保持 fixture、拓扑、实测链路和原生 host backing，调整 `target.pool.hot_slots` 与 `hisparse_config.device_buffer_size`，同时重新绑定目标及调度摘要。六个案例预先固定的最大上下文为 5,206 tokens。安装源码的 `mem_cache/sparsity/factory.py` 接受大于等于 top-k 2,048 的容量。`hisparse.cuh` 在 `seq_len <= HOT_BUFFER_SIZE` 时使用保留位置并返回空缺页计划。因此 6,144 的源码预期是这些请求的 decode H2D 缺页清零，原生写回仍在。6,144 与独立 8,192 控制工件的动态共享内存估计分别为 46,608 和 51,216 B，后者涉及动态共享内存 opt-in。两者的 live JIT、packed KV parity、设备内存和配对服务计时均待实测。

CUDA R2/R3 的配对时间使用项目执行器的固定块物化和计时合同。6,144/8,192 工件属于 stock SGLang 的独立强基线，计时和对照应按其自身的真实服务合同记录。CUDA 运行原始证据在同目录的 `controller/journal.sqlite`、`controller/rounds/`、`controller/harnesses/` 和 `receipts/`。离线演示包含六轮、60 个 API 台账条目和 528 份回执，包含每案例前 32 条动作及完整动作类型计数。四个场景均可查看输入，v7 实测观测归属 Agent 场景。 [离线证据演示](agent-v7-evidence.html)
