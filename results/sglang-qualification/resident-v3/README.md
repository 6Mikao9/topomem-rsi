# 全驻留冷备份省略：工程探针 v3

该独立探针验证人工实现的受信原语。原生 6144 槽热缓存与全驻留版本各进行了两次字节资格、两次独立计时。四次资格的生产者地址、完整 656 B 行、输出和实际全局批次完全一致，四次计时继续匹配同一轨迹。实际 worker 的 NCCL 映射和进程组退出均通过核验。

| 配对顺序 | 原生 6144 / ms | 全驻留 / ms | 原生减全驻留 / ms |
| --- | ---: | ---: | ---: |
| 原生 → 全驻留 | 1110.875540 | 1082.872624 | +28.002916 |
| 全驻留 → 原生 | 1094.854361 | 1066.375246 | +28.479115 |

指标是两个 rank 的固定实测请求组从首个提交到最后完成的总窗口，包含完整模型 prefill 和 decode，排除引擎初始化和前一组预热。这里有两对公开用例观测；它们用于选择值得接入的受信原语，稳定性能结论需独立的正式评估。模型为固定的随机初始化后玩具文本微调 checkpoint，本实验没有应用质量结论。

每个 rank 的冷 KV 主机 payload 从 129,226,752 B 降到 0 B，增加六个 CUDA 指针占位行，共 3,936 B 逻辑字节。热 payload 维持 64,739,328 B，工作器统计的热元数据维持 1,011,776 B。该元数据口径包含固定请求映射，容量校准报告的 coordinator 热元数据口径为 879,616 B。冷主机 payload、GPU 逻辑张量和 CUDA allocator 分配/预留是不同指标，本探针没有把冷主机内存节约称为显存下降。

每个 rank、每次资格检查了 756 次交换和 756 个 newest 行；rank 0 还逐字节核对了 1,548,162 个选中历史行。独立 producer 坐标先验证物理位置，再验证字节，拒绝同值的错误别名。性能进程不创建该 shadow oracle。v3 的 producer 摘要格式与旧冷备份观察器不同；此资格逐次比较同一新格式的原生与全驻留进程。正式适配器另行统一 canonical 摘要并重新做源码资格。

读取计时数值前，另存的 `topomem-resident-integration-decision-plan-v1.json` 记录了工程接入规则：两个配对均超过 5 ms、所有正确性门槛通过。该规则绑定的是工程接入决策，所选原语还需加入正式手写对照。这里没有模型生成调用，也没有递归生成器晋级。

`artifacts.json` 与 `audit.json` 记录原包及全部成员摘要。原始回执字节保持不变。重建摘要：

```sh
python -B build_audit.py --evidence resident-v3-evidence.zip --output reconstructed-audit.json
```

独立源包的 `README_ZH.md` 包含实机命令。它要求先通过相邻 `ingress-v1` 的固定门槛，使用由操作员提供的私有启动配置，串行取得 GPU 租约；所有新运行使用新输出目录。
