# Topology-bound HiSparse serving

This SGLang 0.5.20 adapter changes the physical storage of complete cold KV layer slabs. The original coordinator owns request slots, the hot cache and eviction. The original DSA decode path consumes the resulting hot KV via FlashInfer sparse MLA. The external runtime fixes rank placement, admission, scheduling and requests.

The configurable path also selects a startup native hot-capacity setting under a measured budget. The checkpoint is a tiny architecture-test model with random initialization followed by toy-text fine-tuning. Its observed replay emits EOS. The qualification scope is actual packed KV, DSA selections and execution semantics for these fixed requests. Language quality and trained-model KV locality remain outside that scope. [Model provenance and configurable deployment](../../docs/SG_CONFIGURABLE_RELEASE.md)

The adapter accepts local GPU, pinned host, directly addressable peer GPU and explicit two-hop pinned relay. A relay reads misses with the native swap planner, transfers indices and payload through pinned memory, then invokes the native planned-copy kernel. Its fixed scratch footprint is part of the same cold backing budget used by all arms. The scope here is independent requests. Fixture session and branch identifiers are labels for analysis.

## Inputs

- `target.json` declares `schema` 1, `gpu_bindings` by topology node, `model_config_sha256`, `model_weights_sha256`, `pool`, `native_host` and `allowed_nodes`. Each GPU binding carries `ordinal`, `uuid`, `name` and `[major, minor]` `capability`. `pool` carries `rows`, `layers`, `page_size` and `hot_slots`. `allowed_nodes` maps each compute node to its permitted storage nodes. Derive the shape from the qualified engine. Compute ranks occupy the first visible CUDA ordinals in rank order.
- `topology.json` contains the common incremental cold-memory budgets, fixed device nodes and measured links. The supported transport labels are `pinned_h2d`, `pinned_d2h` and `cuda_p2p`. Provide a measured file matching each selected edge's `evidence_sha256`. For a relay the two paths use the same pinned host node. The runner allocates one shared host pool per worker and requires the pinned host topology node to match the deployment's memory domain.
- `fixture.json` contains `schema` 1, `name`, `warmup` and `requests`. Each row contains `rid`, `arrival_ms`, `max_new_tokens` and exactly one of `input_ids` or `prompt`. Optional `session` and `branch` fields are preserved in the result. Arrival times are relative to their warmup or measured phase. The client submits those arrivals while SGLang decides dispatch.
- `scenario.json` is a `MemoryScenario`. Use `rsi_memory.topology.fingerprint` on the target and fixture dictionaries for `target_sha256` and `workload_sha256`. Compute `schedule_sha256` from `fingerprint(sglang_serving.schedule_inputs(fixture, tp_size, selector))`. The supported selector labels are `torch-unfused` and `sgl-kernel`.
- The native arm uses the bound host-only pool. Supply a frozen `kv_memory_program` to each manual or generated arm. The manual program is the hand-authored control. All arms use the same topology and budgets. The implementation accepts the `allocate/place` rule subset. The compiled reservation plan records each layer's selected read and write edges.

## Run order

1. Qualify both visible devices and the intended route. `python -B -m integrations.topology_memory.sglang_route_probe --mode staged --compute-device 0 --peer-device 1 --output <new.json>` exercises the native backup and swap kernels against a byte oracle. Its timing covers storage transfer and swap operations.
2. Run `python -B -m integrations.topology_memory.sglang_serving --model <model> --target <target.json> --topology <topology.json> --scenario <scenario.json> --fixture <fixture.json> --link-evidence <measurement.json> --output <new-dir> --arm native --phase parity`. Repeat `--link-evidence` as needed.
3. For `--arm manual` or `--arm generated`, add `--program <frozen.json>` and `--qualification <native-parity/result.json>`. `--require-remote` makes the run fail unless the compiled program places cold KV on a separate GPU. Parity checks selected packed KV for every decode layer and rank, deterministic output IDs and actual dispatch.
4. Run `--phase performance` with `--qualification` pointing to that same arm's successful parity result and a fresh output directory. The unprofiled request stream provides TTFT, TPOT and throughput. The runner enforces the qualified dispatch and output IDs and keeps separate backing, relay and Torch allocator ledgers.

`generate_serving_case` builds the target, scenario and replay bundle from explicit GPU bindings, the pool shape, model content digests and measured link files. It previews the native and optional hand-authored plan before writing a new case directory. GPU qualification happens separately.

For backbone TP2 with attention DP2, pass two `--compute-node` arguments in CUDA order and `--attention-dp-size 2` to the case builder. Each request needs `routed_dp_rank` set by the external workload. Include both ranks in warmup and measured requests. The runner binds global workers to two GPUs while each local HiSparse coordinator sees an attention TP group of one. Parity checks each rank's assigned requests and requires a selected attention miss to consume bytes from any configured peer tier.

`python -B -m integrations.topology_memory.generate_dp2_case --profile <torch-profile.json> --briefing <briefing.json> --supplement <appendix.md> --model-config-sha256 <digest> --model-weights-sha256 <digest> --output <new-dir>` builds the authored DP2 qualification case. The example briefing and appendix live under `examples/topology_memory`. The builder verifies the raw synchronized pinned-copy samples and copies their exact bytes into the case. It uses the measured `h2d` and `d2h` directions for explicit pinned routes. The fits characterize the profiling CPU affinity and copy primitive. Shared contention, serving latency and serving performance remain separate observations. Pass `--tokenizer <local-model-dir>` to validate that every authored prompt exceeds 4,096 hot slots and fits within 8,192 tokens with its 64-token decode budget.

`manual_program.json` is the untuned one-local-slab heuristic. `relay_witness_program.json` is a separate hand-written qualification policy that sends one slab per rank to its peer through pinned host memory. Qualify the witness as `--arm manual --require-remote` after native parity. Both share the same cold caps with the all-host native baseline. The case records no generated result or timing result.

`python -B -m integrations.topology_memory.tune_sglang_manual --calibration-case <calibration-case> --calibration-result <completed-native-parity-dir> --evaluation-case <separately-frozen-case> --output <new-dir>` makes a manual control from native per-layer cold miss counts. It selects the highest observed miss layer per rank with ties going to the smaller layer index. The tuner consumes calibration warmup and measured rows, verifies their aggregate totals, records their raw log digests and reads only target, topology and scenario metadata for evaluation. This selects a manual policy by a miss-count proxy. Live latency and output parity still require the same serving qualification and measurement as any candidate.

## Independent native probes

On GLM DSA with packed FP8 on SM120, the installed backend requires FlashInfer sparse MLA. The available small decode variant starts at eight query heads. Sharding this checkpoint's eight heads over two attention ranks leaves four per rank. `sglang_dp_smoke` probes a different, fixed configuration with backbone TP2 and attention DP2. It submits one request to each attention DP rank and records the actual local head count and request dispatch.

The installed HiSparse validation requires radix cache to be disabled. Its request completion path releases the physical hot and cold KV before session cache completion. `sglang_radix_probe` uses stock DSA with the default UnifiedRadixCache and HiSparse disabled. It binds the Python tree core and its sole FULL device component. It checks page-aligned shared physical mappings for two native session branches, disjoint retained suffixes and output parity with isolated full-context references. Its scope is immutable shared prefix pages with independently written suffixes. Partial-page copy and simultaneous HiSparse relay are outside the probe's scope.
